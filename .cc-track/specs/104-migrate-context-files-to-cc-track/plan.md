## Summary

Migrate all cc-track owned context files from `.claude/` to `.cc-track/` to avoid Claude Code's new permission prompts on the `.claude/` folder. This is a systematic find/replace across the codebase, updating path references in TypeScript files, templates, slash commands, config files, and documentation.

## Phase 0: Research & Decisions

### Key Decisions

#### Decision: Directory Name `.cc-track/`
- **Chosen**: `.cc-track/` (hidden directory with hyphen)
- **Rationale**: Matches project name, hidden by default, distinct from `.claude/`
- **Alternatives Considered**:
  - `.cctrack/` - Less readable
  - `cc-track/` - Not hidden, clutters directory listing
  - `.track/` - Too generic, could conflict
- **Tradeoffs**: Slightly longer to type, but clearer purpose

#### Decision: Migration via Instructions (not scripts)
- **Chosen**: `/migrate` command provides instructions for Claude to follow
- **Rationale**: User confirmed - trust Claude to execute migration steps correctly
- **Alternatives Considered**:
  - Automated bash script - More fragile, less flexible
  - TypeScript migration script - Over-engineered for one-time use
- **Tradeoffs**: Depends on Claude's reliability, but allows for edge case handling

#### Decision: No Backward Compatibility
- **Chosen**: Clean break - `.cc-track/` only, no fallback to `.claude/`
- **Rationale**: Simpler codebase, cleaner migration path
- **Alternatives Considered**:
  - Check both locations - Adds complexity, delays full migration
- **Tradeoffs**: Users must migrate, but `/specify` gates on this

## Phase 1: Design

### Migration Command Instructions

The `/migrate` command will be updated to include instructions for Claude to:

1. **Check preconditions**:
   - Verify `.claude/` directory exists
   - Check if `.cc-track/` already exists (handle merge case)

2. **Create new directory**:
   - `mkdir -p .cc-track/specs`

3. **Move cc-track files** (explicit list):
   - `specs/` → `.cc-track/specs/`
   - `backlog.md` → `.cc-track/backlog.md`
   - `cc-track-workflow.md` → `.cc-track/cc-track-workflow.md`
   - `code_index.md` → `.cc-track/code_index.md`
   - `constitution.md` → `.cc-track/constitution.md`
   - `decision_log.md` → `.cc-track/decision_log.md`
   - `learned_mistakes.md` → `.cc-track/learned_mistakes.md`
   - `no_active_task.md` → `.cc-track/no_active_task.md`
   - `plans-archive/` → `.cc-track/plans-archive/`
   - `product_context.md` → `.cc-track/product_context.md`
   - `progress_log.md` → `.cc-track/progress_log.md`
   - `research/` → `.cc-track/research/`
   - `system_patterns.md` → `.cc-track/system_patterns.md`
   - `track.config.json` → `.cc-track/track.config.json`
   - `user_context.md` → `.cc-track/user_context.md`

4. **Leave in `.claude/`**:
   - `settings.json`
   - `settings.local.json`
   - Any user-created files not in the list above

5. **Update CLAUDE.md**:
   - Replace all `@.claude/` imports with `@.cc-track/`
   - Preserve any user customizations

6. **Verify migration**:
   - Confirm all files moved successfully
   - Test that `@` imports still work

### Path Update Pattern

For each file type, use consistent replacement:

**TypeScript path.join patterns**:
```typescript
// Before
join(cwd, '.claude', 'track.config.json')
// After
join(cwd, '.cc-track', 'track.config.json')
```

**Regex patterns**:
