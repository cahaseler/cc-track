# Implementation Plan: Fix Plugin Script Execution

**Feature ID**: `102`
**Branch**: `102-fix-plugin-script-execution`
**Created**: 2025-10-15
**Spec**: @.claude/specs/102-fix-plugin-script-execution/spec.md

## Summary

Slash commands in the cc-track plugin cannot execute TypeScript scripts because `${CLAUDE_PLUGIN_ROOT}` is not available in bash execution triggered by the `!` prefix. This implementation creates a SessionStart hook that copies scripts to a platform-specific directory (`~/.local/share/cc-track/scripts/` on Linux, `%LOCALAPPDATA%\cc-track\scripts\` on Windows) and sets the `CC_TRACK_SCRIPTS_ROOT` environment variable. All 8 slash commands will be updated to reference this new variable, enabling reliable script execution across all session types.

## Phase 0: Research & Decisions

### Research Questions
1. ✅ **Resolved**: How do hooks output context to Claude? → JSON with `hookSpecificOutput.additionalContext`
2. ✅ **Resolved**: What environment variables are available in slash commands? → Custom env vars set by hooks ARE available
3. ✅ **Resolved**: Platform-specific paths? → XDG Base Directory (Linux), %LOCALAPPDATA% (Windows)
4. ✅ **Resolved**: How to detect platform in bash? → `uname` for OS detection
5. ✅ **Resolved**: JSON parsing in bash? → `jq` (assumed available per spec dependencies)

### Key Decisions

#### Decision: TypeScript for SessionStart Hook
- **Chosen**: TypeScript hook executed via `bun run` (matching all other hooks)
- **Rationale**:
  - Consistency with existing hooks (edit-validation.ts, pre-tool-validation.ts)
  - Cross-platform support (Bun works on Linux and Windows)
  - Type safety and better error handling
  - Access to Node.js APIs (fs, path, process)
  - Can be unit tested with existing test infrastructure
- **Alternatives Considered**:
  - Bash script: Doesn't work reliably on Windows, inconsistent with project patterns
  - Python script: Not available on all systems, adds dependency
- **Tradeoffs**: Slightly more verbose than bash, but much more maintainable and consistent

#### Decision: Copy All Scripts on Version Change Only
- **Chosen**: Compare `.version` file with current plugin version, only copy if different
- **Rationale**:
  - Performance: Avoid unnecessary file I/O on every session start
  - Reduces wear on SSD/flash storage
  - Still catches all plugin updates reliably
- **Alternatives Considered**:
  - Always copy: Wasteful, slow on every startup
  - Never copy (symlink): Doesn't work across different filesystem locations
  - Hash comparison: Overkill for this simple use case
- **Tradeoffs**: Slightly more complex logic, but significant performance benefit

#### Decision: Platform Detection via `process.platform`
- **Chosen**: Node.js `process.platform` API for OS detection
- **Rationale**:
  - Cross-platform API available in Bun runtime
  - Returns 'linux', 'win32', 'darwin' consistently
  - No external commands needed
  - Type-safe and testable
- **Alternatives Considered**:
  - `uname` command: Bash-specific, doesn't work in TypeScript context
  - Environment variables: Not reliable across platforms
- **Tradeoffs**: None - this is the standard approach for Node.js/Bun

#### Decision: Graceful Failure with Warning
- **Chosen**: Continue session startup even if script installation fails, output warning to stderr
- **Rationale**:
  - Never block user from starting Claude Code
  - SessionStart hooks cannot block (per Claude Code design)
  - User can fix permissions/disk space and restart
- **Alternatives Considered**:
  - Fail hard: Would prevent Claude Code from starting (bad UX)
  - Silent failure: User wouldn't know something is wrong
- **Tradeoffs**: Commands will fail if installation failed, but user is warned

#### Decision: Update allowed-tools to Match Execution Path
- **Chosen**: Change `allowed-tools` in slash commands to reference `${CC_TRACK_SCRIPTS_ROOT}`
- **Rationale**:
  - Permission checking should match actual execution path
  - Consistency between allowed-tools and execution command
  - Avoids confusion in debugging
- **Alternatives Considered**:
  - Keep `${CLAUDE_PLUGIN_ROOT}` in allowed-tools: Would be misleading
  - Remove allowed-tools: Would lose permission control
- **Tradeoffs**: None - this is strictly better

## Phase 1: Design & Implementation Details

### SessionStart Hook Design

#### Hook Registration (hooks/hooks.json)
```json
{
  "SessionStart": [
    {
      "name": "session-start",
      "script": "bun run ${CLAUDE_PLUGIN_ROOT}/hooks/session-start.ts",
      "description": "Installs plugin scripts to user directory and sets CC_TRACK_SCRIPTS_ROOT"
    }
  ]
}
```

#### Hook Script Logic (hooks/session-start.ts)
```typescript
// ABOUTME: SessionStart hook that copies plugin scripts to platform-specific user directory
// ABOUTME: and sets CC_TRACK_SCRIPTS_ROOT environment variable for slash command execution

import { existsSync, mkdirSync, copyFileSync, readFileSync, writeFileSync, readdirSync } from 'fs';
import { join } from 'path';
import { homedir } from 'os';

interface SessionStartInput {
  session_id: string;
  transcript_path: string;
  cwd: string;
  hook_event_name: 'SessionStart';
  source: 'startup' | 'resume' | 'clear' | 'compact';
}

async function main() {
  try {
    // 1. Read stdin for hook input
    const input: SessionStartInput = JSON.parse(await Bun.stdin.text());

    // 2. Determine platform-specific installation directory
    const scriptsRoot = process.platform === 'win32'
      ? join(process.env.LOCALAPPDATA || join(homedir(), 'AppData', 'Local'), 'cc-track', 'scripts')
      : join(homedir(), '.local', 'share', 'cc-track', 'scripts');

    // 3. Set environment variable (for this process and children)
    process.env.CC_TRACK_SCRIPTS_ROOT = scriptsRoot;

    // 4. Create scripts directory if needed
    try {
      mkdirSync(scriptsRoot, { recursive: true });
    } catch (err) {
      console.error(`⚠️  Failed to create ${scriptsRoot} - check permissions`);
      process.exit(0); // Exit 0 to not block session
    }

    // 5. Get plugin root and version
    const pluginRoot = process.env.CLAUDE_PLUGIN_ROOT || join(__dirname, '..');
    const pluginJsonPath = join(pluginRoot, '.claude-plugin', 'plugin.json');

    let pluginVersion = 'unknown';
    try {
      const pluginJson = JSON.parse(readFileSync(pluginJsonPath, 'utf-8'));
      pluginVersion = pluginJson.version || 'unknown';
    } catch {
      // If can't read version, always copy
    }

    const versionFilePath = join(scriptsRoot, '.version');
    const installedVersion = existsSync(versionFilePath)
      ? readFileSync(versionFilePath, 'utf-8').trim()
      : '';

    // 6. Copy scripts if version changed
    if (pluginVersion !== installedVersion) {
      const scriptsSourceDir = join(pluginRoot, 'commands', 'scripts');

      try {
        const scriptFiles = readdirSync(scriptsSourceDir).filter(f => f.endsWith('.ts'));

        for (const file of scriptFiles) {
          copyFileSync(
            join(scriptsSourceDir, file),
            join(scriptsRoot, file)
          );
        }

        writeFileSync(versionFilePath, pluginVersion, 'utf-8');
      } catch (err) {
        console.error(`⚠️  Failed to copy scripts to ${scriptsRoot}: ${err}`);
        process.exit(0); // Exit 0 to not block session
      }
    }

    // 7. Output context for Claude
    const output = {
      hookSpecificOutput: {
        hookEventName: 'SessionStart',
        additionalContext: `cc-track scripts installed at: ${scriptsRoot}\nEnvironment variable CC_TRACK_SCRIPTS_ROOT is set for command execution.`
      }
    };

    console.log(JSON.stringify(output));
    process.exit(0);

  } catch (err) {
    console.error(`⚠️  SessionStart hook error: ${err}`);
    process.exit(0); // Exit 0 to not block session
  }
}

main();
```

**Key Features**:
- TypeScript with type safety
- Cross-platform via `process.platform` and `path` module
- Graceful error handling (never blocks session)
- Version-based conditional copying
- JSON output for Claude context
- Consistent with existing hook patterns

#### Error Scenarios
| Scenario | Handling | User Experience |
|----------|----------|----------------|
| Permission denied | Log warning to stderr, exit 0 | Warning visible in Claude Code output, session continues |
| Disk full | Log warning to stderr, exit 0 | Warning visible, session continues |
| Missing plugin.json | version="unknown", always copy | Scripts work, minor performance hit |
| Partial copy failure | Individual file copy errors caught | Later command failures for missing scripts, but session started |
| Missing CLAUDE_PLUGIN_ROOT | Fallback to `__dirname/..` | Works from typical plugin structure |

### Technical Risks
- **Risk**: Permission denied creating scripts directory
  - **Likelihood**: Medium (some corporate environments restrict home directory writes)
  - **Impact**: High (slash commands won't work)
  - **Mitigation**: Clear error message tells user to fix permissions, session continues

- **Risk**: Bun runtime not available
  - **Likelihood**: Very Low (required by cc-track plugin)
  - **Impact**: Critical (hook won't run)
  - **Mitigation**: Part of plugin installation requirements

### Dependency Risks
- **Risk**: `${CC_TRACK_SCRIPTS_ROOT}` not propagated to slash command execution
  - **Likelihood**: Low (tested pattern from superpowers plugin)
  - **Impact**: Critical (commands won't execute)
  - **Mitigation**: Manual testing in Phase 5, fallback to ask user to restart Claude Code

- **Risk**: Plugin directory structure changes in future
  - **Likelihood**: Low (structure is stable)
  - **Impact**: Medium (hook can't find scripts to copy)
  - **Mitigation**: Use `${CLAUDE_PLUGIN_ROOT}` which adapts to plugin location

## Implementation Notes
*Additional context for implementers*

### Key Patterns to Follow
- **Error handling**: All failures should log to stderr and exit 0 (never block session)
- **Path operations**: Use Node.js `path` module for cross-platform compatibility
- **Platform detection**: Use `process.platform` ('linux', 'win32', 'darwin')
- **Version tracking**: Simple string comparison, no semver parsing needed
- **Dependency injection**: Not critical for this hook (minimal testable logic)

### Testing Strategy
- **Unit tests**: Can test core logic if extracted to helper functions
  - Platform path determination
  - Version comparison logic
  - File listing/filtering
- **Manual testing required**:
  1. Fresh session startup → verify scripts copied, env var set
  2. Session resume → verify version check, no re-copy if version same
  3. Plugin update simulation → change version in plugin.json, verify re-copy
  4. Permission failure → chmod directory read-only, verify graceful warning
  5. Each slash command → verify execution with new path

### Performance Considerations
- **Version check first**: Avoid unnecessary file copying on every session
- **Individual file copy**: `copyFileSync` per file for error handling
- **Minimal JSON parsing**: Only parse plugin.json version field
- **No network calls**: Everything is local filesystem operations
- **Synchronous operations**: Acceptable since hook runs on startup (not user-blocking)

### Windows-Specific Notes
- `process.env.LOCALAPPDATA` provides `C:\Users\<username>\AppData\Local`
- `path.join()` handles backslash vs forward slash automatically
- Bun runtime provides consistent cross-platform APIs
- No bash-specific features needed
