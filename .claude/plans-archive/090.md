## Fix Semantic Release by Using Squash Merge Strategy

### The Problem
Semantic-release is not creating releases for our merged PRs because:
1. GitHub creates merge commits with `Merge pull request #...` as the title
2. The conventional commit message (`feat: complete TASK_XXX`) is in the body
3. Semantic-release only analyzes the commit title by default
4. Using `mergePattern` in parserOpts would break regular commit detection

### The Solution
Switch to **squash merging** for PRs, which creates a single commit with the PR title as the commit message.

### Implementation Steps

1. **Update GitHub repository settings**:
   - Set squash merge as the default (or only) merge method
   - Configure to use PR title for squash merge commits
   
2. **Update the complete-task command** to ensure PR titles follow conventional commit format:
   - Modify `src/commands/complete-task.ts` to create PRs with conventional commit titles
   - Current PR title format: "Complete TASK_XXX"
   - New format: "feat: complete TASK_XXX - [Task Title]"

3. **Create a manual release for the already-merged changes**:
   - Create an empty commit with proper conventional format to trigger the release
   - This will release all the changes since v1.39.0

4. **Document the new merge process** for future contributors

### Code Changes Needed

In `src/commands/complete-task.ts`, update the PR creation to use conventional commit format:
```typescript
// Change from:
const prTitle = `Complete ${taskId}`;

// To:
const prTitle = `feat: complete ${taskId} - ${taskTitle}`;
```

### Immediate Action
After implementing the changes, create a manual trigger commit:
```bash
git commit --allow-empty -m "feat: trigger release for accumulated changes

Includes:
- TASK_089: Fix Markdown Parsing Issue in Task Creation"
```

This approach:
- ✅ Works with semantic-release without custom configuration
- ✅ Maintains clean commit history with squash merges
- ✅ Ensures all PRs trigger appropriate releases
- ✅ Doesn't break regular commit detection
