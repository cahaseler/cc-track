## Project Notes

cc-track context window pressure points:
- System patterns file is comprehensive but maybe too detailed for every session
- Decision log grows over time and is always loaded
- Spec folders contain multiple files (spec.md, plan.md, tasks.md, progress.md) all loaded
- Active task context includes full git diffs during review

The spec-driven workflow actually makes this worse in some ways:
- More structured documentation = more tokens per feature
- Separation of concerns (good for clarity) = more files to load (bad for context)
- Constitution + clarification + planning = thorough but verbose

Potential optimizations:
1. Lazy-load decision log (only relevant entries, not full file)
2. Compress system_patterns into concise rules
3. Context tiers: Always-load vs On-demand
4. Store more state externally (logs, reviews) rather than in-context
5. Explicit session boundaries with state checkpoints
