## Project Notes

Design patterns for effective cc-track subagents:

**Test Generation Subagent:**
```
Input: 
- File path to implementation
- Function/class to test
- Testing framework/patterns to use

Process:
- Read implementation file
- Generate comprehensive test cases
- Write to test file

Output:
- Success/failure message
- Path to test file
- Brief summary of test coverage

Primary agent gets: Small message, not full test code
```

**Research Subagent:**
```
Input:
- Research question
- Sources to check (docs URLs, codebase patterns, etc.)

Process:
- Read documentation
- Search codebase for examples
- Synthesize findings

Output:
- research.md with structured findings
- Recommendations with evidence

Primary agent gets: Summary only, reads full file if needed
```

Both fit the pattern: Output is much smaller than work performed, coordination is simple (task description + success/failure), primary agent doesn't need to see all the intermediate steps.
