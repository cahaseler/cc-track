## Project Notes

**TASK_094: WebSearch Year Validation Implementation**

Added smart year detection to prevent Claude from searching for outdated years (e.g., "TypeScript 2024" when it's 2025).

**Architecture Decisions:**
- Extended existing pre-tool-validation hook rather than creating new hook (cleaner, single validation point)
- WebSearch validation runs first, then file-based validations (logical separation of concerns)
- Used regex patterns instead of LLM for performance (< 5ms vs potential 2-3s for SDK call)

**Integration Points Identified:**
1. Hook dispatcher (hook.ts:25) - Must route WebSearch to pre-tool-validation
2. Hook function (pre-tool-validation.ts:269) - WebSearch-specific logic
3. Settings.json - WebSearch PreToolUse matcher with 5s timeout
4. Track.config.json - websearch_validation feature flag

**Pattern Detection Strategy:**
- 4 regex patterns cover common cases: end-year, start-year, latest/current, documentation
- Separate isHistoricalSearch() for exemptions (comparisons, elections, temporal refs)
- Returns suggested query in denial message for better UX

**Files Modified (10 total):**
- Core: pre-tool-validation.ts, hook.ts, types.ts
- Config: settings.json, track.config.json, templates/track.config.json, init.ts
- Tests: pre-tool-validation.test.ts (21 new tests)
- Docs: README.md

- Historical patterns need flexibility: "2024 presidential campaign" requires `\w*\s*` between year and keyword
- Multiple integration points (dispatcher + settings) can cause silent failures
